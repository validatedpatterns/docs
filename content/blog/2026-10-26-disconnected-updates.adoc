== Preamble

Identifying every operator, container image, and Helm chart for a pattern is an
extremely cumbersome chore—especially when remote charts use wildcard versions.
We wanted to help with that artifact collection without putting more burden on
the technician gathering the images.

We also assumed that person may need images, operators, and Helm charts for
workflows that are not strictly pattern-related, so `--extra-config` lets you
merge additional content into the generated mirror set.

The disconnected workflow centers on three steps:

. `patternizer airgap init` — scrape the pattern and generate an oc-mirror
  `imagesetconfig.yaml` (plus helpers)
. `patternizer airgap bootstrap` — apply disconnected registry/Git/CatalogSource
  settings into the pattern values from an `airgap:` block in your secrets file
. `./pattern.sh make install-airgap` — install while injecting CA trust and
  registry credentials so Argo CD can sync

== Patternizer Updates

If you're not familiar with the `patternizer` utility, see the
https://github.com/validatedpatterns/patternizer[patternizer GitHub repository].

There are several ways to run it:

.Run patternizer directly with podman
[source,bash]
----
podman run --pull=newer -v "$PWD:$PWD:z" -v "$HOME:$HOME:z" -w "$PWD" \
  quay.io/validatedpatterns/patternizer
----

Or add a function to `~/.bashrc` or `~/.zshrc`:

.Add patternizer function to your rc file
[source,bash]
----
patternizer() {
  podman run --pull=newer \
    -v "$PWD:$PWD:z" \
    -v "$HOME:$HOME:z" \
    -w "$PWD" \
    quay.io/validatedpatterns/patternizer "$@"
}
----

Open a new terminal session or `source` your rc file after adding the function.

=== What's happening

`--extra-config` merges additional operators, images, and Helm entries into the
generated <<imagesetconfig>>.

`--ocp-version` includes the OpenShift platform channel and tags OLM catalogs /
CatalogSources for that release.

[NOTE]
====
When omitted, catalog tagging defaults to 4.22. Override with `--ocp-version`,
or edit `${output-dir}/imagesetconfig.yaml` before mirroring.
====

Patternizer scrapes the repository for operators, container images, and Helm
charts. When a remote chart uses a wildcard version, the command resolves the
latest from the chart repository. The pattern is cloned with full history so
pushing into your airgapped Git service does not fail on shallow clones.

.Additional arguments
|===
|--clone-dir string | Directory for Git clones (default: --output-dir)
|--cluster-groups string | Comma-separated cluster group names (default: all)
|--download-oc-mirror | Download oc-mirror archives into --output-dir
|--extra-config string | External YAML with operators, additionalImages, and helm.local entries to merge into imagesetconfig
|--git-ref string | Branch or tag to clone when the source is a Git URL
|--helm-repo string | OCI registry/org for Validated Patterns charts (default "quay.io/validatedpatterns")
|-h --help | Help for init
|--ocp-version string | Include OpenShift platform channel stable-<version> and tag OLM catalogs / CatalogSources (e.g. 4.22)
|--output-dir string | Directory for generated artifacts (default "./airgap-out")
|--registry string | Optional mirror registry hostname for values-disconnected.yaml and mirror-commands.sh
|--skip-oci-resolve | Skip live OCI chart version resolution and image discovery (wildcards will not be resolved)
|===

== Copy and update values-secret to your home directory

.Procedure: Configure secrets for the airgap deployment
[source,bash]
----
cp ~/mcgodemo/multicloud-gitops/values-secret.yaml.template \
  ~/values-secret-multicloud-gitops.yaml
----

Something we wanted to improve was removing the guesswork from disconnected
deployments. Instead of hunting which Secret or ConfigMap Argo CD needs for
your registry or Git host, an `airgap:` block in the values-secret file drives
that for you. (Same `path` / `value` field style as Vault secrets; it is *not*
loaded into Vault.)

You need the CA for your Git server and either a dockerconfig JSON or
username/password for the mirror registry.

.Example: values-secret-<pattern>.yaml
[source,yaml]
----
secrets:
  - name: config-demo
    vaultPrefixes:
    - global
    fields:
    - name: secret
      onMissingValue: generate
      vaultPolicy: validatedPatternDefaultPolicy
airgap:
  argocdNamespace: vp-gitops
  patternsOperatorNamespace: patterns-operator
  certificates:
    - name: gitea
      fields:
      - name: host
        value: gitea.airgap.rhuk.lab
      - name: ca
        path: ~/gitea_container_certs/cert.pem
      - name: clusterProxy
        value: "true"
      - name: argocdTLS
        value: "true"
    - name: mirror-registry
      fields:
      - name: host
        value: mirror.airgap.rhuk.lab
      - name: ca
        path: /etc/pki/ca-trust/source/anchors/quay-rootCA.pem
      - name: clusterProxy
        value: "true"
      - name: argocdTLS
        value: "true"
  registries:
    - name: mirror
      fields:
      - name: url
        value: mirror.airgap.rhuk.lab:8443
      - name: dockerconfig
        path: ~/.docker/config.json
      # Or username + password file instead of dockerconfig:
      # - name: username
      #   value: init
      # - name: password
      #   path: /path/to/registry.password

  # Disconnected pattern values (rendered into values-global.yaml + variants)
  registry: mirror.airgap.rhuk.lab:8443
  ocpVersion: "4.22"   # derives cs-*-operator-index-v4-22
  # Or declare CatalogSources explicitly (overrides ocpVersion derivation):
  # catalogSources:
  #   redhat: cs-redhat-operator-index-v4-22
  #   community: cs-community-operator-index-v4-22
  # Or discover from the cluster (requires oc / kubeconfig):
  # discoverCatalogs: true
  # renderValues: true   # default when registry/ocpVersion/catalogSources set
----

== patternizer airgap bootstrap

.Procedure: patternizer airgap bootstrap
[source,bash]
----
patternizer airgap bootstrap ~/mcgodemo/multicloud-gitops/ \
  --output-dir ./airgap-bootstrap \
  --discover-catalogs \
  --secrets-file ~/values-secret-multicloud-gitops.yaml
----

`patternizer airgap bootstrap` does the following:

* Ingests the `airgap:` section from `~/values-secret-multicloud-gitops.yaml`
* Discovers CatalogSources from the cluster (with `--discover-catalogs`)
* Updates `values-global.yaml` and variant values
  (`variants/hub/values-{hub,standalone}.yaml`) with those CatalogSources,
  `helmRepoUrl`, and related disconnected fields

[#lab-environment]
== Lab environment used in this post

All testing for this post was done from a laptop running KVM/libvirt. DNS for
the guests comes from libvirt's dnsmasq. An isolated host-only network named
`airgap` (`192.168.127.0/24`) has no outbound internet path. A single bastion VM
on that network hosts Git, the mirror registry, and the install load-balancer /
HTTP services. The Single Node OpenShift (SNO) node sits on the same L2 segment.

In this lab, Git and the mirror share the bastion IP under different DNS names.
From the cluster's point of view they are local HTTPS services—exactly what the
`airgap.certificates` and `airgap.registries` entries in the values-secret file
refer to.

=== Topology

* Hypervisor: laptop (KVM/libvirt + dnsmasq)
* Network: `airgap` / `192.168.127.0/24` (no outbound internet)
* Bastion: `bastion.airgap.rhuk.lab` → `192.168.127.5`
* SNO node: `sno0` → `192.168.127.11`
* Names that resolve to the bastion IP:
  `mirror.airgap.rhuk.lab`, `gitea.airgap.rhuk.lab`,
  `api.airgap.rhuk.lab`, `api-int.airgap.rhuk.lab`

=== Services on the bastion

[cols="1,2,2"]
|===
| Role | Hostname / endpoint | Purpose

| Mirror registry
| `https://mirror.airgap.rhuk.lab:8443`
| Quay mirror-registry. Holds OCP release content, operators, and pattern
  images/charts. Patternizer `airgap.registries` and cluster pull secret /
  IDMS/ITMS point here. Trust the Quay root CA
  (`quay-rootCA.pem`) via `airgap.certificates`.

| Git (Gitea)
| `https://gitea.airgap.rhuk.lab:3000`
| Gitea in a podman container. Pattern repos are pushed here after
  `airgap init`; Argo CD uses this as the Git origin. Trust
  `~/gitea_container_certs/cert.pem` via `airgap.certificates`.

| API / apps VIP
| `api.airgap.rhuk.lab`, `api-int.airgap.rhuk.lab`, apps wildcard → bastion IP
| HAProxy on the bastion fronts API and ingress traffic for the SNO node during
  and after agent-based install.

| Agent / install assets
| HTTP on the bastion
| httpd serves agent ISO / install assets while the cluster is coming up.
|===

[#gitea-startup]
=== Gitea on the bastion

Gitea runs as a podman container with HTTPS on port 3000. TLS material lives in
`~/gitea_container_certs` (`cert.pem` / `key.pem`), and a named volume holds
Gitea data. Prefer pulling the image from the local mirror so the bastion never
needs internet:

.Example: start Gitea from the mirrored image
[source,bash]
----
GITEA_HOSTNAME=gitea.airgap.rhuk.lab
GITEA_HTTP_PORT=3000
GITEA_SSH_PORT=2222
GITEA_IMAGE=mirror.airgap.rhuk.lab:8443/rhpds/gitea:1.27.3
GITEA_CERT_DIR=~/gitea_container_certs
GITEA_ROOT_URL=https://${GITEA_HOSTNAME}:${GITEA_HTTP_PORT}/

podman volume exists gitea-data || podman volume create gitea-data

podman run -d --name gitea --net=host \
  -e GITEA__database__DB_TYPE=sqlite3 \
  -e GITEA__server__PROTOCOL=https \
  -e GITEA__server__DOMAIN="${GITEA_HOSTNAME}" \
  -e GITEA__server__HTTP_PORT="${GITEA_HTTP_PORT}" \
  -e GITEA__server__ROOT_URL="${GITEA_ROOT_URL}" \
  -e GITEA__server__CERT_FILE=/data/gitea/https/cert.pem \
  -e GITEA__server__KEY_FILE=/data/gitea/https/key.pem \
  -e GITEA__server__SSH_DOMAIN="${GITEA_HOSTNAME}" \
  -e GITEA__server__SSH_PORT="${GITEA_SSH_PORT}" \
  -e GITEA__server__SSH_LISTEN_PORT="${GITEA_SSH_PORT}" \
  -v gitea-data:/data:Z \
  -v "${GITEA_CERT_DIR}:/data/gitea/https:ro,Z" \
  "${GITEA_IMAGE}"
----

Create the empty `multicloud-gitops` repository in the Gitea UI (or API), then
push as shown earlier in <<scp>> / Repo Configuration.

[#agent-install]
=== Agent-based OpenShift install (summary)

Patternizer assumes a reachable disconnected cluster; this lab brings that
cluster up with the
https://docs.openshift.com/container-platform/latest/installing/installing_with_agent/[OpenShift agent-based installer]
so nothing in the install path needs internet.

High-level sequence:

. Mirror OCP release + operators into Quay on the bastion (`oc-mirror` against
  the generated `imagesetconfig.yaml`)
. On the bastion, write disconnected `install-config.yaml` and `agent-config.yaml`
. Build the agent ISO with `openshift-install agent create image` (using a
  local RHCOS live ISO and pull access to the mirrored release)
. Run HAProxy + httpd on the bastion so `api` / `api-int` / apps DNS names and
  install assets are available on the airgap network
. Attach the agent ISO to the SNO VM, boot it, wait for the disk image write to
  finish, then boot from disk
. Wait for install complete from the bastion
. Apply mirror-published cluster resources (IDMS/ITMS, CatalogSources), then
  continue with patternizer bootstrap / `install-airgap`

==== What goes into the agent configs

The disconnected pieces that matter for agent install are in
`install-config.yaml`:

* `pullSecret` — credentials for `mirror.airgap.rhuk.lab:8443`
* `additionalTrustBundle` — Quay mirror-registry root CA
* `imageDigestSources` — map release / operator source registries to the
  bastion mirror (produced by oc-mirror / publish)

`agent-config.yaml` stays network-focused for the SNO host:

* `rendezvousIP` — the SNO address on the airgap network
* Static interface / MAC / DNS / gateway (no DHCP dependency for install)
* `additionalNTPSources` — bastion IP, so time sync works without public NTP

.Example shape (illustrative)
[source,yaml]
----
# install-config.yaml (disconnected bits)
pullSecret: '{"auths":{"mirror.airgap.rhuk.lab:8443":{...}}}'
additionalTrustBundle: |
  -----BEGIN CERTIFICATE-----
  ... quay root CA ...
  -----END CERTIFICATE-----
imageDigestSources:
  - source: quay.io/openshift-release-dev/ocp-release
    mirrors:
      - mirror.airgap.rhuk.lab:8443/openshift/release-images
  - source: quay.io/openshift-release-dev/ocp-v4.0-art-dev
    mirrors:
      - mirror.airgap.rhuk.lab:8443/openshift/release

# agent-config.yaml
rendezvousIP: 192.168.127.11
additionalNTPSources:
  - 192.168.127.5
hosts:
  - hostname: sno0.airgap.rhuk.lab
    role: master
    interfaces:
      - name: enp1s0

==== Build, boot, and wait

On the bastion (with `openshift-install` and registry auth configured):

[source,bash]
----
# After install-config.yaml + agent-config.yaml are in the install directory:
openshift-install agent create image --dir /root/airgap

# Monitor from the bastion once the node is booting the agent ISO:
openshift-install agent wait-for install-complete \
  --dir /root/airgap --log-level debug
----

Two practical notes from this lab:

* Do not switch the VM from CDROM to disk at the first
  `Writing image to disk: 100%` if the OS disk still looks empty—wait until the
  disk has a real partition table / has grown, then detach the ISO and boot from
  disk.
* After the cluster is up, apply the IDMS/ITMS and CatalogSource manifests from
  your mirror publish workspace so OLM pulls operators from
  `mirror.airgap.rhuk.lab:8443`. That is the cluster state
  `patternizer airgap bootstrap --discover-catalogs` expects to find.

At that point the pattern path in the main post continues: push the repo to
Gitea, configure `airgap:` in the values-secret file, bootstrap, and
`./pattern.sh make install-airgap`.

=== Assumptions

* Bastion and SNO share the airgap network and can resolve the DNS names above
* Mirror registry and Gitea CAs are available as PEM files for
  `airgap.certificates` in `~/values-secret-*.yaml`
* Pattern Git history is pushed to Gitea before `./pattern.sh make install-airgap`
* Cluster CatalogSources / IDMS/ITMS already target
  `mirror.airgap.rhuk.lab:8443` (or you discover CatalogSources at bootstrap time)
* Agent install completed with pull secret + trust bundle + image digest sources
  pointed at the bastion mirror
